## CSS: reguła „łagodząca" przegrywa kaskadę z definicją bazową (2026-09-06, client-site)

**Blizna:** blok `@media (prefers-reduced-motion: reduce)` miał spowolnić marquee i aurorę
zamiast je gasić. Nie działał — dwa razy z rzędu, z dwóch różnych powodów:
1. niżej w pliku stał starszy duplikat `.marquee-track { animation: none }` (ta sama
   specyficzność, późniejsza pozycja → wygrywa),
2. po jego usunięciu bazowa definicja `.marquee-track { animation: marquee 38s ... }`
   nadal stała PO bloku łagodzącym i nadpisywała `animation-duration`.

**Reguła:** bloki `prefers-reduced-motion` (i każdy inny blok „nadpisujący zachowanie")
trzymaj **na końcu arkusza**, po wszystkich definicjach bazowych. Przy równej specyficzności
o wyniku decyduje kolejność, a nie intencja.

**Bramka:** nie ufaj lekturze CSS. Sprawdź `getComputedStyle(el).animationName` +
`animationDuration` w obu trybach (`browser_context(reduced_motion=...)`) — jedna komenda,
zero domysłów. Wzorzec: `tools/scrub_check.py` w tym repo.

**Skąd wyszło:** ux-reviewer w pg-review (finding REDUCED-MOTION-CASCADE-DEAD-CODE) złapał
