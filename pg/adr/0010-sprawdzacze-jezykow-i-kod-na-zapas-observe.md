# ADR-0010: Sprawdzacze top języków w hookach i bramka „kod na zapas” (observe)

Data: 2026-10-26 | Status: przyjęte (uzytkownik 2026-10-26: „czy nasz PG ma realnie compilator kodów w językach, w których piszemy? … czy jest zabezpieczenie przed pisaniem niepotrzebnego kodu?”, potem „rób punkty 1-4” i „miejmy pewność, że chociaż top języki mamy możliwość dobrze pisać”)

**Kontekst:** `hooks/lib/lint-file.js` sprawdzał tylko TS/JS (eslint/oxlint, tsc), Pythona (ruff, pyright), JSON i CSS.
- Edycja `.go`/`.rs`/`.java`/`.sh` nie przechodziła przez żaden kompilator, a `gates.jsonl` zapisywał przy niej `ran: 1 files`. Na laptopie były już go, cargo/clippy, gcc/g++, javac, shellcheck i deno, ale nic ich nie wołało.
- Nie istniała zasada „nowy język → najpierw narzędzia”. Szablon CI obsługiwał tylko npm.
- Kod pisany „na zapas”: twarde bramki łapały tylko powielone literały i zakomentowany kod. knip/jscpd w CI działały informacyjnie (`|| true`), a rubryka 9 `product-reviewer` (gold-plating) działała tylko przy T3.
- Top języki według GitHub Octoverse 2025 i Stack Overflow Survey 2025: TS, Python, JS, Java, C#, C++, C, PHP, Shell, Go, SQL, Rust.
- Flota dziś (2026-10-26, `find ~/src ~/D/repo ~/Desktop ~/Documents/PG`): 0 plików .go/.rs/.java/.cs/.php/.cpp; .c: 8, .sh: 88 (+ TS/Python). Sprawdzacze Go/Rust/Java/C#/PHP/C++ = **gotowość** na prośbę uzytkownika („miejmy pewność, że top języki możemy dobrze pisać”), nie odpowiedź na bieżący kod.

**Decyzja:**

| Problem | Mechanizm | Odrzucona alternatywa (dlaczego) |
|---|---|---|
| Brak sprawdzaczy poza TS/JS/Python | `hooks/lib/lang-checkers.js` — JEDYNA lista język → narzędzie: Go (gofmt + go vet), Rust (cargo clippy/check), Shell (shellcheck, także pliki bez rozszerzenia z shebangiem), Java (javac), C/C++ (gcc/g++ -fsyntax-only), PHP (php -l), C# (dotnet build), Deno edge fn (deno check) | dopisanie języków wprost w `lint-file.js` (plik rośnie, a lista zmienia się najczęściej, więc chowa ją jeden moduł — Parnas); LSP serwery (stan, długi start, w hooku bez sensu) |
| Fałszywe `ran` | `ran` liczy tylko pliki w języku ze sprawdzaczem; kod bez sprawdzacza → `skipped: no checker for .ext` + raz na rozszerzenie w sesji `[lang-gap]` dla modelu (`loop-monitor.js`) | ciche ignorowanie (to był błąd); sygnał tylko w guard_health (model nie wie w trakcie pracy) |
| Zakres „kodu” | `isCodeFile` w `lint-file.js` obejmuje nowe języki i kod bez sprawdzacza — świadomie: to samo pojęcie liczy stop-gate (tier, wymóg recenzji), więc edycja `.go`/`.kt` nie wygląda już jak „sama dokumentacja” | osobna lista dla stop-gate (dwa źródła prawdy, rozjazd) |
| Wstrzyknięcie przez nazwę pliku | narzędzia wołane BEZ powłoki (`spawnSync(tool, argv)`, `--` przed plikami); test z nazwami `a$(touch X).sh`, `b;touch X;.c` + mutant `shell:true` zabity | escapowanie dla powłoki (łatwo o lukę; pg-review security: PoC na wersji z `shell:true`) |
| Narzędzia wykonujące kod repo | cargo (build.rs, proc-macro) i dotnet (MSBuild) tylko pod korzeniem z `pg/trusted-roots.txt` — drzewo cwd sesji NIE wystarcza (obcy klon w katalogu roboczym); wpisy listy tylko absolutne na tej platformie (`C:\\dev` na Linuksie = `<cwd>/c:/dev`, blocker z PoC w r2, `pg/cases.md` › FOREIGN-PLATFORM-PATH-RESOLVED-AGAINST-CWD — poprawka w `hooks/lib/trusted-roots.js`, chroni też lint i qa-matrix); go poza tymi korzeniami bez cgo; bez sieci: GOPROXY=off, GOTOOLCHAIN=local, `--offline`, `--no-restore`, `deno check --no-lock` (+ `--cached-only` poza drzewem cwd) | uruchamianie zawsze (RCE w obcym klonie); zaufanie do cwd (pg-review security); zawsze pomijanie (Rust/C# bez kontroli) |
| Wyciek treści spoza repo | gcc/g++ z `-fno-diagnostics-show-caret`; do agenta wraca tylko diagnostyka z lokalizacją w repo (`repoDiagnostics`, po `realpath` — symlink w repo na plik spoza = spoza). Poza `pg/trusted-roots.txt` komunikaty WSZYSTKICH sprawdzaczy zredagowane do `plik:linia: error [KOD]` (`redact`): treść błędu potrafi nieść bajty pliku spoza repo (`#embed` + szablon, PoC na g++ 15, pg-review security r2) | pełny stderr (`#include "/etc/..."` cytuje plik); filtr tylko po lokalizacji (obchodzi go `#embed` i symlink); skip wszystkich obcych repo (Go/Shell/PHP w klonach bez sprawdzenia) |
| Obcy klon: narzędzie czyta INNE pliki repo | reguła: poza exec-trust zostają tylko sprawdzacze czytające wyłącznie edytowane pliki — gofmt, php -l, shellcheck z `--norc` (`.shellcheckrc` repo włączał `source=/dev/zero`: 3,3 GB w 3 s) i pod `prlimit --as=2G`; go vet (cały pakiet), javac (`-sourcepath`), deno (importy; `prlimit` nie działa na V8), gcc/g++ (`.gch`), cargo, dotnet = skip z powodem (pg-review security r3-r6) | łatanie narzędzie po narzędziu (r3-r6: każda runda nowy wariant tej samej klasy); limit cgroup `systemd-run --scope -p MemoryMax=` (zależność od sesji systemd użytkownika w hooku, start ~100 ms na wywołanie) |
| Obcy klon POD zaufanym korzeniem | wpis listy to cały katalog (`~/src`), a leżał tam już klon z GitLaba (security r3); exec-trust (cargo, dotnet, cgo, gcc, deno, javac, brak redakcji) = `trustedForExec` w `lang-checkers.js`: (1) ścieżka korzenia BEZ symlinków (== realpath; narzędzie idzie po przodkach ścieżki, którą dostaje — symlink w obcym klonie do własnego repo dawał Directory.Build.props obcego autora, r13) i w `pg/trusted-roots.txt`; (2) repo liczone od TOPLEVEL z `git -c safe.bareRepository=explicit`, git-dir = `<toplevel>/.git` albo worktree/submoduł (osadzone bare repo, r8); (3) KAŻDY `remote.*.url` na koncie `owner` z `pg/fleet-scope.json` albo zero remote (`clone -o upstream`, fork z obcym upstream, r10); (4) to samo REKURENCYJNIE dla repo nadrzędnego nad toplevel, max 8 poziomów — cargo/MSBuild/shellcheck czytają config przodków, własny submoduł w obcym superprojekcie wykonał rustc-wrapper (r11, PoC). Katalog bez gita = lokalny projekt (known-limits) | lista repo zamiast korzeni (każde nowe repo = edycja warstwy kontrolnej); sam komentarz „nie dodawaj obcych klonów” (nieegzekwowany) |
| Binarny `.gch` z repo | gcc/g++ po cichu ładuje `<h>.gch` zamiast `<h>` (zrzut stanu kompilatora) z każdego katalogu, do którego sięgnie `#include "../.."` → C/C++ poza exec-trust = skip, jak cargo/dotnet (pg-review security r3/r5) | skan repo na `*.gch` (r3→r5: dziury w node_modules, głębokości, korzeniu bez `.git` — heurystyka bez końca); flaga wyłączająca PCH (gcc jej nie ma) |
| Plik specjalny w include | gcc/g++ pod `prlimit --as=2G`: `#include "/dev/zero"` kończy się w < 1 s skipem „limit pamięci” | sam timeout 60 s (w tym czasie gcc zjada RAM) |
| Wiele projektów .NET w katalogu | 1 `.csproj` = jawny argument `dotnet build`; > 1 = skip (MSB1011 to nie błąd kodu, pg-review code r2) | blokada na MSB1011 (fałszywe trafienie) |
| Budżet hooka | sprawdzacze dostają `deadline` (stop-gate: budżet − 20 s); < 5 s do końca = `skipped`, nie start narzędzia | stały timeout 60 s na narzędzie (kilka języków = przekroczony timeout hooka, ubity bez werdyktu) |
| Brak zależności projektu (Maven, nagłówki CMake, `go mod download`, restore) | `skipped` z powodem, nigdy blokada | blokada (fałszywe trafienia uczą obchodzenia bramek, GATE-FALSE-POSITIVE-TEACHES-BYPASS) |
| Ostrzeżenia w starym kodzie | Rust blokuje ostrzeżenia tylko w EDYTOWANYCH plikach; C/C++ i C# blokują tylko błędy (brak flag z systemu budowania) | `-D warnings` dla całego repo (blokuje na długu historycznym — ZAKRES) |
| „Nowy język” nie ma procedury | `pg/design.md` › F.10 + `guard_health`: RED, gdy w oknie 7 dni kod bez sprawdzacza w >= 3 różnych plikach (1-2 = info) albo sprawdzacz bez narzędzia | sama proza w CLAUDE.md (reguła na papierze); RED od 1 zdarzenia (post-edit + stop-gate logują ten sam plik 2×, jeden plik `.kt` = alarm) |
| CI tylko npm | job `Polyglot (Python/Go/Rust/CSharp/PHP/Java/Shell)` w `templates/repo/.github/workflows/quality.yml`, narzędzia z obrazu ubuntu-latest, ruff/pytest/pyright przypięte, `timeout-minutes: 20`; `bin/mas_branch_protect.py` wymaga tego checka tylko, gdy quality.yml repo go ma | akcje setup-* (nowe SHA do przypięcia bez potrzeby; obraz ma te narzędzia); wymagany check zawsze (repo ze starym quality.yml = merge stoi na zawsze) |
| Kod na zapas | `bin/unused-export-gate.js` w pre-push, OBSERVE: nowy eksport TS/JS albo def/class Pythona bez żadnego użycia w repo → ostrzeżenie + `would_block`; `product-reviewer` w `optional_reviewers` od T2 | knip w hooku (ładuje configi repo = wykonuje kod repo; nie ma go w node_modules floty); blokada od razu (ADR-0008: blokada dopiero po incydencie); product-reviewer jako wymagany przy T2 (koszt limitu bez dowodu zysku) |

**Odrzucone alternatywy:** (1) LSP serwery per język (stan, długi start, w hooku bez sensu); (2) jeden zewnętrzny meta-linter, np. MegaLinter/super-linter (kontener ~GB, wolny w post-edit, wykonuje configi repo); (3) knip w pre-push zamiast własnego `unused-export-gate` (ładuje configi repo, nie ma go w node_modules floty); (4) blokada od razu zamiast observe (ADR-0008); (5) product-reviewer WYMUSZANY przez stop-gate przy T2 (blokada zakończenia bez dowodu zysku) — zamiast tego `optional_reviewers`: orkiestrator pg-review odpala go przy T2 zawsze (koszt: 1 agent sonnet na recenzję T2, świadomy), ale jego brak niczego nie blokuje; (6) SQL w `lang-checkers.js` — SQL to migracje, a te ma już `bin/sql-migration-lint.js` (pre-commit, pg-review); druga ścieżka = dwa źródła reguł.

**Pomiar przed włączeniem:** `unused-export-gate` na 3 repo floty (workshop-app-team: 30 commitów, bsm-bot, app-v5-vercel) dał 0 trafień na 363 nowe definicje, więc ostrzeżenie nie stanie się szumem. Test syntetyczny łapie przypadek z martwym eksportem.

**Świadomie przyjęte koszty:**
- C/C++ bez `compile_commands.json`: brakujący nagłówek = skip, więc część plików nie zostanie sprawdzona (widać to w telemetrii).
- Java bez classpath Mavena/Gradle: brak biblioteki = skip — lokalnie realnie sprawdzany jest tylko kod bez zależności; pełna kontrola w CI przez wrapper.
- Kotlin, Swift, HCL, Ruby, Dart, Vue/Svelte/Astro nie mają sprawdzacza (`no checker`). Dodajemy je, kiedy pojawi się realny kod (F.10).
- `unused-export-gate` nie widzi użyć dynamicznych (`obj[name]`). Publiczne API paczki (package.json main/exports) i konwencje frameworków są pomijane jawnie. Powód w telemetrii stały (`unused-export: nowe definicje bez uzycia`, liczba w `count`); brak `origin/main` = `skipped`.
- CI: brak kroku C/C++ (każde repo ma inny system budowania — krok cmake/make dopisuje repo) i Deno (brak na obrazie; sprawdza hook lokalny).
- Koszt cykliczny: każda nowa wersja narzędzia (go, cargo, dotnet, deno na laptopie; przypięte ruff/pyright w CI) może zmienić diagnostykę — przypięte wersje podbijamy świadomie, lokalne narzędzia z apt idą z systemem; guard_health pokazuje `tool missing`.
- Lista szczegółowych granic: `pg/known-limits.md` › Sprawdzacze języków.

**Blokada od pierwszego dnia (świadome odstępstwo od „start w observe”, ADR-0008):** sprawdzacze języków BLOKUJĄ na wyniku kompilatora/lintera od razu. ADR-0008 dotyczy reguł heurystycznych (tekst komendy, wzorce), których trafność trzeba zmierzyć. Kompilator to deterministyczna pętla weryfikacji tej samej klasy co istniejące `tsc`/`ruff` w tym samym hooku (CLAUDE.md › Dźwignia jakości). Klasy fałszywych trafień ze środowiska (brak zależności, nagłówka, restore, wiele projektów, limit pamięci, budżet) idą do `skipped`, nie do blokady. Koszt: shellcheck/gofmt/go vet patrzą na CAŁY edytowany plik, więc stare ostrzeżenia w edytowanym pliku blokują jak w eslint (Rust: tylko ostrzeżenia w edytowanych plikach).

**Wycofanie:** jeden język = usuń jego wpis z `CHECKERS` w `hooks/lib/lang-checkers.js` (pliki trafią do `skipped: no checker` — luka widoczna, nic nie blokuje); całość = w `hooks/lib/lint-file.js` usuń wywołanie `langs.runCheckers`; `unused-export-gate` = usuń blok w `git-hooks/pre-push` (observe, niczego nie blokuje); product-reviewer = wpis w `OPTIONAL_REVIEWERS` (`hooks/lib/risk-tier.js`). Każde z nich = zmiana warstwy kontrolnej (fraza CONTROL_PLANE) + `node bin/pg-seal.js`. Kryterium usunięcia języka: 0 zdarzeń `ran`/`blocked` dla jego rozszerzeń przez 6 miesięcy przy kosztach utrzymania (zmiany diagnostyki narzędzia) → przegląd.

**Przy okazji:** `git-hooks/pre-push` — zmienne pętli `read` z prefiksem `_` (SC2034 z nowego shellchecka w hooku; zachowanie bez zmian). `bin/test_hooks_v3.js` — fikstura ścieżki domowej z jednoliterowym użytkownikiem -> `/home/user/` (eksport publiczny dopuszcza tylko `user`/`runner`/`you`; test name-lang bez zmiany sensu). `.gitignore` — `/skills/synced/` (cudze skille synchronizowane z innego źródła trafiały do diffu i blokowały stop-gate jako obce pliki; uzytkownik 2026-10-26: „tak, dopisz”).

**Miara (przegląd 2026-11-23; licznik w guard_health info, `hooks/lang_gap_health.py`):** `would_block` z `unused-export-gate` (ile pushy / definicji, dedup po `head`; trafność = ręczna ocena listy `items`) → decyzja o blokadzie; `skipped: no checker` i `tool missing` z guard_health → kolejne języki; czy product-reviewer przy T2 znalazł choć jeden gold-plating.
